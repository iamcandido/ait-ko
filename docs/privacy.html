AiT.KO – Privacy Policy

Last updated: October 27, 2026

AiT.KO is a browser extension that lets Okta administrators describe what they want to look up in the Okta Admin API (for example users, groups, applications, or system log events) in plain language. It turns the request into a read-only API request, runs it against the administrator's own Okta organization, and lets them export the results to CSV or JSON. This policy explains what data the extension handles and where it goes.

In short: the developer does not operate any server, does not collect any data, and does not receive any data from the extension. The only data that leaves your browser, other than requests to your own Okta organization, is the text of your request and your API key, which are sent to the AI provider that you choose and configure.

3. What we do not do

  • We do not run any server and do not receive, collect, or have access to your data, your requests, or your API key.
  • We do not use analytics, tracking, advertising, or crash-reporting services.
  • We do not sell or transfer user data to third parties, and we do not use it for any purpose unrelated to the extension's single purpose.
  • We do not use or transfer user data to determine creditworthiness or for lending purposes.
  • We do not load or execute remotely hosted code.
  • We do not send Okta data to AI providers. Only the text of your request is sent.

The extension's use of information complies with the Chrome Web Store User Data Policy, including the Limited Use requirements.

4. Third-party AI providers

When you click "Generate request", the text you typed is sent directly from your browser to the provider you selected in the extension options:

  • Google Gemini API, subject to Google's terms and privacy policy. Please note that Google's terms for free-tier usage may allow content submitted to be used to improve Google's products. Check Google's current Gemini API terms for details.
  • Anthropic Claude API, subject to Anthropic's commercial terms and privacy policy.

If you leave the model setting empty, or click "List available models" in the options, the extension also asks the selected provider which models your key can use. That request contains only your API key, with no request text and no Okta data.

We do not control how these providers handle data. Do not include personal data (such as a specific person's name or email address) in your requests unless you are comfortable with it being processed by the selected provider. Generic requests such as "active users in the Finance department with country code PT" contain no personal data.

5. Permissions and why they are needed

  • storage: to keep your API key (in memory for the browser session by default, or on your computer if you choose) and your provider and model choices.
  • Access to *.okta.com and *.oktapreview.com: to display the AiT.KO panel on the Okta Admin Console and to call your own Okta organization's read-only Admin API with your existing session. The panel activates only on hostnames that contain -admin.; on all other Okta pages it does nothing.
  • Access to generativelanguage.googleapis.com: to send your request text to the Google Gemini API, if you select that provider.
  • Access to api.anthropic.com: to send your request text to the Anthropic API, if you select that provider.

6. Security

  • The extension only performs read (HTTP GET) requests against the Okta Admin API, limited to a fixed allowlist of resource paths (such as users, groups, applications, system log, and policies). It never creates, changes, or deletes anything in your Okta organization.
  • The request produced by the AI provider is treated as untrusted and validated before it runs: only allowlisted paths, query parameters, and search operators are accepted, and anything else is rejected. You can see and edit the request before running it, and it is validated again when you run it.
  • As a precaution, response fields whose names look like secrets (for example client secrets, passwords, or API keys) are replaced with "[redacted]" before results are displayed or exported.
  • Results are rendered as plain text, never as HTML, and CSV exports neutralize spreadsheet formula injection.
  • By default, your API key is held only in memory for the browser session and is never readable by the scripts that run inside web pages. You can choose to save it on your computer instead: encrypted with a passphrase (AES-GCM, with the encryption key derived from your passphrase using PBKDF2), or unencrypted. A forgotten passphrase cannot be recovered; you would simply enter the API key again. If you choose the unencrypted option, anyone with access to your browser profile on disk could read the key. Whichever you choose, we recommend a dedicated key that you can revoke at any time.

7. Retention and deletion

The extension keeps no data other than your API key (in memory for the session by default, or on your computer if you choose), provider, and model name. You can delete them at any time with "Forget key" on the options page, or by removing the extension, which deletes all of its local data. Data held by an AI provider is governed by that provider's policies.

8. Children
